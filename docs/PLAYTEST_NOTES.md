# Coin Tower Web 플레이 관측

## 2026-10-07 — 첫 웹 플레이 버전의 입력·진행 관측

- 빌드: `0.1.0`, 첫 웹 플레이 구현(2026-10-07). 이후 검증된 체크포인트로 로컬 Git에 기록.
- 환경: macOS, Chromium 데스크톱 및 Pixel 7 크기·터치 에뮬레이션. 실제 휴대폰 검사는 아니다.
- 방법: Playwright 개발 환경 16개 시나리오. 마우스 클릭·브라우저 터치 이벤트를 사용했고, 긴 적층은 개발 전용 시간 제어와 상태 관측을 함께 사용했다. 화면 캡처도 직접 확인했다.
- 가설: [설계의 관찰할 가설](GAME_DESIGN.md#관찰할-가설과-남은-결정). 기능 검증 전체 결과는 [VALIDATION.md](VALIDATION.md).

### 가설 상태

| 가설                                                    | 결과                                        | 다음 확인                                                                             |
| ------------------------------------------------------- | ------------------------------------------- | ------------------------------------------------------------------------------------- |
| 원본 속도 곡선·판정 폭이 웹에서도 읽기 쉬운 도전을 만듦 | 판단 유보                                   | PC 마우스와 실제 휴대폰으로 각각 5·10·20개 구간을 플레이하고 실패 이유·속도 체감 기록 |
| Perfect·화면 이동이 다음 탭을 방해하지 않음             | 판단 유보                                   | 연속 Perfect에서 손가락 가림·시선 이동·탭 누락·x4 빈도 관찰                           |
| 같은 논리 경로를 유지하면 크기별 템포가 같음            | 논리 이동량은 확인, 플레이 체감은 판단 유보 | 실제 기기와 창 크기를 바꿔 왕복 시간·지연 체감 비교                                   |

자동 측정만으로 재미·최종 난이도·터치 감각을 확정하지 않는다. 합의된 시작값은 변경하지 않았다. 다음 제안은 실제 Android/iPhone과 PC에서 짧게 반복 플레이하며 위 세 가설을 관찰하는 것이다.

화면 관측 중 일시정지 제목이 이동 동전을 일부 가리는 배치를 발견해 제목은 위로, 메뉴는 목표 아래로 옮겼다. 이후 검사에 제목·메뉴 경계와 하단 버튼 사이 간격을 추가했다. 이 배치 수정은 게임 수치나 판정 규칙을 바꾸지 않는다.

배포 화면에서 HUD 판 누락도 관측했다. CSS 배경 이미지 디코딩 검사로 실패를 재현하고 URL 기준을 수정했다. 배포 캡처도 다시 확인했다.
