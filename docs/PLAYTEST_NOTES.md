# Coin Tower Web 플레이 관측

## 2026-10-08 — 결과·메뉴의 두 기록과 경신 표시 관측

- 대상: 설계 체크포인트 `a379481` 이후 작업본의 결과 비교 표·메뉴 기록 두 칸·항목별 `NEW BEST`. 저장 형식 v2·속도·판정·Perfect 연출·아트는 유지했다.
- 방법: Chromium 데스크톱 마우스·Pixel 7 터치 에뮬레이션. 판 준비는 개발 시간 제어와 합성 입력, 마지막 실패는 실제 마우스·터치로 진행했다. 별도로 개발 훅 없이 브라우저 Clock과 실제 입력으로 Perfect 1회 → 실패 → 메뉴 → 새로고침을 확인했다. 사람 플레이 피드백은 아니다.
- AI 화면 관측: 기존 최고 30·x8에서 이번 판 20·x12인 결과는 `COINS` 20/30, `PERFECT COMBO` x12/x12이고 콤보 행만 경신 배지가 붙는다. 높이만·둘 다 경신, 동점, 콤보 x0·x1·x100도 구분한다. 메뉴는 두 개인 최고를 같은 크기의 파란 패널과 금색 숫자로 표시한다.
- 화면 크기: 360×640·390×844 결과와 821×462 가로 포털 결과·메뉴 캡처를 확인했다. x100 값과 두 경신 배지가 패널 안에 들어오며 제목·안내·버튼 영역과 겹치지 않는다. 메뉴 기록 패널은 동전 아트 위에서 끝난다. 자동 경계 검사도 함께 사용했다.
- 수정 근거: 360px 폭에서 제목 PNG 사각형과 결과 패널의 7px 겹침을 발견해 패널을 아래로 조정하고 배지 글자를 키웠다. 모바일 연속 리사이즈 직후의 검사는 Phaser FIT 반영 전 캔버스 경계를 읽었으므로 실제 크기 반영을 기다리게 수정했다. 브라우저 Clock 검사에서 세 번째 동전도 Perfect로 놓였던 준비 오류는 목표 밖으로 이동한 뒤 실패 입력을 보내도록 고쳤다. 이 준비 수정으로 게임 규칙을 바꾸지 않았다.
- 가설 상태: 두 기록과 배지의 공간적 비가림·값 대응은 화면과 자동 관측으로 지지된다. 사용자가 결과에서 경신 항목을 바로 알아보는지와 실제 작은 화면의 읽기 편함은 판단 유보다. 실기기 조정은 사용자 요청대로 보류한다.
- 다음 관측: 향후 PC 사람 플레이에서 높이만·콤보만 경신한 결과의 배지를 보고 어떤 기록을 갱신했는지 바로 구분하는지 확인한다. 전역 리더보드 정책·서비스는 별도 범위다.

## 2026-10-08 — 무제한 콤보 숫자 관측

- 대상: 무제한 콤보·완료 시 최장 콤보 저장 변경. 이전 체크포인트 `9d4ba64` 이후의 작업본이며 자동 검사 근거는 [VALIDATION.md](VALIDATION.md)에 기록한다.
- 방법: Chromium 데스크톱 마우스·Pixel 7 터치 에뮬레이션. 개발 시간 제어로 x5·x6·x13을 실제 포인터 입력으로 진행했다. x100은 합성 입력으로 x99까지 준비한 뒤 마지막 착지만 실제 마우스/터치로 진행했다. 사람의 성공률·자연 발생 빈도 근거가 아니다.
- AI 화면 관측: `stack-combo.png`의 x13, `combo-x100.png`의 PC·모바일 x100에서 숫자를 읽을 수 있고 패널 안에 들어온다. 콤보·Perfect 영역은 이동 동전과 탑 상단을 덮지 않는다. 두·세 자리 숫자는 기존 글자 크기를 유지하며 더 긴 숫자는 패널 폭에 맞춰 축소한다. Perfect 크기·시간·반짝임은 기존과 같다.
- 저장 관측: x100 도달 후에도 완료 전 저장 키는 없으며, 새로고침하면 해당 판은 사라진다. 단위 검사에서는 `Perfect 8 → NICE → Perfect 5 → 실패`의 기록이 8임을 확인한다. 마지막 연속 횟수나 Perfect 합계를 쓰지 않는다.
- 가설 상태: 두·세 자리의 잘림·공간적 가림 없음은 자동 경계 검사와 화면 관측으로 지지된다. 다음 동전을 겨냥하는 시선 이동·실제 손가락 가림·주의 분산 체감은 판단 유보다. 사용자 요청대로 실기기 조정은 보류한다.
- 다음 관측: 향후 PC 사람 플레이에서 x9→x10 전환 시 다음 낙하를 놓치는지 확인한다. 현재 결과·메뉴의 두 기록 배치와 전역 리더보드는 별도 범위다.

## 2026-10-07 — CrazyGames 영어 화면과 플랫폼 중단 관측

- 방법: Chromium 데스크톱/터치 에뮬레이션의 SDK fixture 검사 및 공식 SDK 원본의 local 환경 실행. SDK 계약의 자동 검증은 [VALIDATION.md](VALIDATION.md)에 구분했다. 사람의 실기기 플레이 피드백은 아니다.
- AI 화면 관측: 일반 세로 화면과 821×462 DPR 1 포털 크기에서 영어 PLAY, CONTINUE, RESTART, MENU, 확인문을 원본 아트와 함께 확인했다. 자체 전체화면 버튼은 표시되지 않으며 동전·목표와 일시정지 조작 영역을 유지한다. 확인문에 남아 있던 한국어 문장을 발견해 영어로 수정하고 캡처·문구 검사를 다시 확인했다.
- AI 측정: 수동 정지와 재개 카운트다운 완료에만 SDK 플레이 전환을 보고하고, 합성 background 전환은 별도로 보고하지 않는다. 플랫폼 mute 해제 후 저장된 사용자 mute를 보존한다. 이 검사는 실제 포털 음소거/전체화면 조작이나 실제 소리 청취를 대신하지 않는다.
- 가설 상태: 5·10·20개 구간의 속도 체감, Perfect 잔상의 주의 분산, 손가락 가림에 대한 판단은 이전과 같이 유보한다. 사용자 요청에 따라 실기기 조정은 보류했으며 이동 속도·판정 폭·Perfect 시간·아트를 바꾸지 않았다.
- 다음 확인: CrazyGames Preview에서 플랫폼 UI와 실제 SDK 통신을 확인한다. 재미·난이도 확정은 그 이후의 사람 플레이 증거가 필요하다.

### 구간별 상태와 시간 폭

성공 n개를 쌓은 **뒤 다음 동전**의 기준이다. 속도는 실행 상태에서 읽었고 시간은 규칙으로 계산했다. 시간 폭은 중앙 목표를 지나는 한 번의 통과에서 양쪽 허용 범위를 합한 값이다.

| 성공 개수 | 속도(논리 px/s) | 편도 이동 | Perfect 가능 시간 폭 | 전체 성공 시간 폭 |
| --------- | --------------- | --------- | -------------------- | ----------------- |
| 5         | 425             | 1.092초   | 78.1ms               | 234.4ms           |
| 10        | 500             | 0.928초   | 66.4ms               | 199.2ms           |
| 20        | 650             | 0.714초   | 51.1ms               | 153.2ms           |

20개 구간의 Perfect 폭은 60Hz 기준 약 3.1프레임, 중앙 시점 기준 앞뒤 약 25.5ms다. 5개 때보다 폭이 약 35% 줄어 타이밍 오차에 민감해질 수 있다는 추론이며, 실제 플레이가 너무 어렵다는 사용자 판단은 아니다.

자동 측정만으로 재미·최종 난이도·터치 감각을 확정하지 않는다. 합의된 시작값은 변경하지 않았다. 다음 제안은 실제 Android/iPhone과 PC에서 짧게 반복 플레이하며 위 세 가설을 관찰하는 것이다.

화면 관측 중 일시정지 제목이 이동 동전을 일부 가리는 배치를 발견해 제목은 위로, 메뉴는 목표 아래로 옮겼다. 이후 검사에 제목·메뉴 경계와 하단 버튼 사이 간격을 추가했다. 이 배치 수정은 게임 수치나 판정 규칙을 바꾸지 않는다.

배포 화면에서 HUD 판 누락도 관측했다. CSS 배경 이미지 디코딩 검사로 실패를 재현하고 URL 기준을 수정했다. 배포 캡처도 다시 확인했다.
