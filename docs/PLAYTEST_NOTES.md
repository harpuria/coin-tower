# Coin Tower Web 플레이 관측

## 2026-10-07 — CrazyGames 영어 화면과 플랫폼 중단 관측

- 방법: Chromium 데스크톱/터치 에뮬레이션의 SDK fixture 검사 및 공식 SDK 원본의 local 환경 실행. SDK 계약의 자동 검증은 [VALIDATION.md](VALIDATION.md)에 구분했다. 사람의 실기기 플레이 피드백은 아니다.
- AI 화면 관측: 일반 세로 화면과 821×462 DPR 1 포털 크기에서 영어 PLAY, CONTINUE, RESTART, MENU, 확인문을 원본 아트와 함께 확인했다. 자체 전체화면 버튼은 표시되지 않으며 동전·목표와 일시정지 조작 영역을 유지한다. 확인문에 남아 있던 한국어 문장을 발견해 영어로 수정하고 캡처·문구 검사를 다시 확인했다.
- AI 측정: 수동 정지와 재개 카운트다운 완료에만 SDK 플레이 전환을 보고하고, 합성 background 전환은 별도로 보고하지 않는다. 플랫폼 mute 해제 후 저장된 사용자 mute를 보존한다. 이 검사는 실제 포털 음소거/전체화면 조작이나 실제 소리 청취를 대신하지 않는다.
- 가설 상태: 5·10·20개 구간의 속도 체감, Perfect 잔상의 주의 분산, 손가락 가림에 대한 판단은 이전과 같이 유보한다. 사용자 요청에 따라 실기기 조정은 보류했으며 이동 속도·판정 폭·Perfect 시간·아트를 바꾸지 않았다.
- 다음 확인: CrazyGames Preview에서 플랫폼 UI와 실제 SDK 통신을 확인한다. 재미·난이도 확정은 그 이후의 사람 플레이 증거가 필요하다.

## 2026-10-07 — 5·10·20개 터치와 Perfect 집중 관측

- 빌드: 첫 웹 플레이 `d121c4e`, 게임 코드·아트·시작값 유지. 재현용 Playwright 설정·시나리오만 추가.
- 환경: macOS의 Chromium, Pixel 7 사용자 에이전트·터치 에뮬레이션, 360×640 및 390×844, 캡처 DPR 1. 실제 Pixel/Android/iPhone 또는 Safari 검사가 아니다.
- 방법: `rtk npm run playtest:touch`, 2개 시나리오·각각 3개 구간. 준비는 합성 입력·시간 제어, 관측은 실시간 왕복 이동과 정확한 중앙에서 시간을 고정한 네이티브 브라우저 터치. 사람의 타이밍 성공률은 측정하지 않았다.
- 근거: `tests/playtest/touch.spec.ts`, `playwright.playtest.config.ts`, ignore된 `test-results/touch-playtest/`의 JSON·PNG. 재실행 방법과 계측 한계는 [개발 안내](DEVELOPMENT.md)의 집중 플레이 테스트 절.

### 구간별 상태와 시간 폭

성공 n개를 쌓은 **뒤 다음 동전**의 기준이다. 속도는 실행 상태에서 읽었고 시간은 규칙으로 계산했다. 시간 폭은 중앙 목표를 지나는 한 번의 통과에서 양쪽 허용 범위를 합한 값이다.

| 성공 개수 | 속도(논리 px/s) | 편도 이동 | Perfect 가능 시간 폭 | 전체 성공 시간 폭 |
| --------- | --------------- | --------- | -------------------- | ----------------- |
| 5         | 425             | 1.092초   | 78.1ms               | 234.4ms           |
| 10        | 500             | 0.928초   | 66.4ms               | 199.2ms           |
| 20        | 650             | 0.714초   | 51.1ms               | 153.2ms           |

20개 구간의 Perfect 폭은 60Hz 기준 약 3.1프레임, 중앙 시점 기준 앞뒤 약 25.5ms다. 5개 때보다 폭이 약 35% 줄어 타이밍 오차에 민감해질 수 있다는 추론이며, 실제 플레이가 너무 어렵다는 사용자 판단은 아니다.

자동 측정만으로 재미·최종 난이도·터치 감각을 확정하지 않는다. 합의된 시작값은 변경하지 않았다. 다음 제안은 실제 Android/iPhone과 PC에서 짧게 반복 플레이하며 위 세 가설을 관찰하는 것이다.

화면 관측 중 일시정지 제목이 이동 동전을 일부 가리는 배치를 발견해 제목은 위로, 메뉴는 목표 아래로 옮겼다. 이후 검사에 제목·메뉴 경계와 하단 버튼 사이 간격을 추가했다. 이 배치 수정은 게임 수치나 판정 규칙을 바꾸지 않는다.

배포 화면에서 HUD 판 누락도 관측했다. CSS 배경 이미지 디코딩 검사로 실패를 재현하고 URL 기준을 수정했다. 배포 캡처도 다시 확인했다.
