## 2026-10-09 — 시간대 배경 전환 브라우저 관측

- 대상: 배경 전환 구현 `fff8181`에 개발 전용 렌더 값 조회와 반복 검사를 추가한 작업본. 배경 이미지·게임 규칙·전환 시간은 수정하지 않았다.
- 방법: Playwright 1.63.0 Chromium의 Desktop Chrome·Pixel 7 터치 에뮬레이션. 개발 시간 제어로 좌우 이동·낙하를 진행하고 실제 마우스·Space·터치 입력으로 25개까지 적층했다. 점수·동전 위치를 직접 덮어쓰지 않았다. 실제 사람의 플레이나 휴대폰 측정은 아니다.
- 관측: 5개 점심, 10개 저녁, 15개 밤, 20개 아침, 25개 점심의 전환을 확인했다. 각 전환의 0·300·600·900·1200ms에 모델과 실제 두 Scene Image를 읽었다. 아래 배경은 불투명하며 위 배경의 alpha는 0·0.15625·0.5·0.84375·1의 부드러운 곡선을 따른다. 완료 시 위 배경을 숨기고 아래 배경을 해당 시간대로 유지한다.
- 화면: PC의 5·10·15·20개 중간 캡처, 모바일의 저녁→밤 중간·밤의 Perfect/X15·20개 아침 복귀 캡처를 직접 확인했다. 확인한 화면에는 검은 빈 구간·띠나 큰 구도 어긋남이 보이지 않는다. 이미지의 세부 질감·선명도 차이는 남아 있으며 모든 프레임의 픽셀 정렬을 보장하는 관찰은 아니다.
- 가독성: 확인한 밤 화면에서 금화·Perfect/X15가 배경과 구분되고, HUD·이동 동전·착지 목표와 겹치지 않는다. 전환 600ms 캡처의 Perfect가 옅어지는 것은 기존 피드백 잔여 시간에 따른 표시이며 배경 alpha를 함께 적용하지 않는다. 사람의 숫자 인식 속도나 주의 분산이 줄었다고 판단하지 않는다.
- 검사 준비 보완: 초기 스크립트가 페이드 대기 후 동전의 반전 방향을 고려하지 않아 6번째 동전을 잘못 떨어뜨렸다. 실제 방향과 반사를 고려하도록 보완했다. 실시간 RAF에서 별도 호출로 읽은 모델·렌더 값의 프레임 차이도 한 호출로 채집해 제거했다. 이는 검사 오류 수정이며 런타임 게임 로직은 변경하지 않았다.
- 가설 상태: 시간대 구분과 겹친 화면의 큰 배치 유지는 캡처로 지지된다. 1.2초가 사람의 플레이에 자연스럽고 방해가 적다는 가설은 판단 유보다. 정지·재개·재시작·실패와 자동 RAF 검사 결과는 [검증 기록](VALIDATION.md)을 따른다.
- 산출물: `test-results/standalone/backgrounds-*/`의 시작·중간·완료·Perfect·재시작·결과 PNG와 모델/렌더 JSON attachment. 재실행 시 교체될 수 있다.
- 다음 관측: PC에서 전환을 포함해 20개까지 플레이하며 시간대 변화를 알아차리는지, Perfect를 읽거나 다음 낙하를 결정하는 데 방해가 되는지 사용자 피드백을 받는다. 실기기 조정은 기존 요청대로 보류한다.

- 후속: 구체적인 불편이 보고되면 해당 화면·구간을 재현해 크기·간격을 조정한다. 실기기 조정은 기존 요청대로 보류한다.

## 2026-10-08 — Perfect 아래 이미지 콤보 숫자

- 대상: `91c1c61` 이후 작업본. 원본 Perfect PNG와 새 금색 X·0~9 PNG를 위·아래 두 줄로 조합한다. 판정·속도·콤보 집계·기록 저장은 유지했다.
- 방법: Chromium 데스크톱 마우스·Pixel 7 터치 에뮬레이션. X1·X2·X10은 개발 시간 제어와 실제 입력으로 도달했다. X100은 X99까지 합성 준비 후 실제 입력으로 착지했다. 별도로 개발 훅 없이 브라우저 Clock과 실제 입력으로 X1을 확인했다. 사람의 플레이 피드백은 아니다.
- AI 화면 관측: 기존 Perfect와 새 글자의 금색 면·흰 하이라이트·적갈색 테두리가 어울린다. X2·X100 캡처에서 위 줄은 Perfect, 아래 줄은 숫자로 구분된다. 360×640·390×844·821×462에서 숫자가 잘리지 않고 다음 이동 동전·탑 상단·일시정지 버튼을 가리지 않는다. 숫자 이미지는 공통 높이를 유지하며 글자 폭은 비례한다.
- 재현 검사: X1·X2·X10·X100의 실제 PNG 이름·디코딩·높이 192px, 행의 좌우 경계와 이동 동전 영역 위쪽 배치를 확인했다. Perfect의 잔여 시간에 따른 불투명도, 일시정지·카운트다운 숨김, 재개 시 남은 표시, 시간 종료 시 숨김을 확인했다. 일반 성공 뒤 표시 초기화와 재시작·새로고침 회귀도 검사했다.
- 제작 과정: 균등 행 자르기는 첫 행 글자의 테두리를 자를 수 있어 알파 경계를 측정한 뒤 투명 간격에서 분리했다. 알파 1 수준의 배경 잡점 대신 알파 > 8의 외곽과 3px 원본 여백을 사용했다. 배경·테두리 재도색 없이 11개 투명 PNG로 내보냈다. 상세는 [제작 기록](art/combo-glyphs.md)에 있다.
- 배포 검사 준비 보완: 모바일 Clock에서 고정 580ms 뒤에도 정착이 남는 사례를 발견했다. 실제 다음 이동 단계까지 16ms씩 진행하도록 바꿨고 PC·모바일 각 3회 반복 검사를 통과했다. 게임 속도나 정착 시간 변경은 없었다.

- 가설: 여러 자리 콤보의 공간적 비가림·같은 높이 정렬은 관측으로 지지된다. 사람의 숫자 인식 속도·다음 탭에 대한 주의 분산·작은 화면 가독성은 판단 유보다. 실기기 체감 조정은 사용자 요청대로 보류한다.

### 구간별 상태와 시간 폭

성공 n개를 쌓은 **뒤 다음 동전**의 기준이다. 속도는 실행 상태에서 읽었고 시간은 규칙으로 계산했다. 시간 폭은 중앙 목표를 지나는 한 번의 통과에서 양쪽 허용 범위를 합한 값이다.

| 성공 개수 | 속도(논리 px/s) | 편도 이동 | Perfect 가능 시간 폭 | 전체 성공 시간 폭 |
| --------- | --------------- | --------- | -------------------- | ----------------- |
| 5         | 425             | 1.092초   | 78.1ms               | 234.4ms           |
| 10        | 500             | 0.928초   | 66.4ms               | 199.2ms           |
| 20        | 650             | 0.714초   | 51.1ms               | 153.2ms           |

20개 구간의 Perfect 폭은 60Hz 기준 약 3.1프레임, 중앙 시점 기준 앞뒤 약 25.5ms다. 5개 때보다 폭이 약 35% 줄어 타이밍 오차에 민감해질 수 있다는 추론이며, 실제 플레이가 너무 어렵다는 사용자 판단은 아니다.

자동 측정만으로 재미·최종 난이도·터치 감각을 확정하지 않는다. 합의된 시작값은 변경하지 않았다. 다음 제안은 실제 Android/iPhone과 PC에서 짧게 반복 플레이하며 위 세 가설을 관찰하는 것이다.

화면 관측 중 일시정지 제목이 이동 동전을 일부 가리는 배치를 발견해 제목은 위로, 메뉴는 목표 아래로 옮겼다. 이후 검사에 제목·메뉴 경계와 하단 버튼 사이 간격을 추가했다. 이 배치 수정은 게임 수치나 판정 규칙을 바꾸지 않는다.

배포 화면에서 HUD 판 누락도 관측했다. CSS 배경 이미지 디코딩 검사로 실패를 재현하고 URL 기준을 수정했다. 배포 캡처도 다시 확인했다.
