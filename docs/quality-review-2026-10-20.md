# Basic Launch 재신청 전 2차 품질 검토

확인일: 2026-10-20. 기준: `55cbd61` 일반 production 빌드(`vite preview`)와 개발 빌드(`?debug`), Chromium. 코드·규칙·자산은 변경하지 않았다. 아래 개선안은 모두 [제안]이다.

[1차 검토](quality-review-2026-10-19.md)는 공식 기준의 항목별 대응(작은 창 가독성, 로딩, 소리)을 다뤘고 해당 권장 사항은 구현됐다. 이번 검토는 리젝 사유가 "overall quality"였다는 점에 맞춰, **심사자가 PC에서 처음 1~2분 플레이할 때 받는 인상**을 직접 캡처로 확인했다.

후속 구현(2026-10-20): 사용자가 권장 순서(3 → 1-A → 2)를 승인해 같은 날 구현했다. 탑 기울기 규칙 변경(2의 마지막 후보)은 제외했다. 확정 규칙은 각 설계 문서, 결과는 [구현 계획](IMPLEMENTATION_PLAN.md)·[검증 기록](VALIDATION.md)을 따른다. 아래 관측은 검토 당시 기준으로 보존한다.

## 판단

기술 요건과 세부 마감은 대부분 정리됐다. 남은 위험은 개별 결함이 아니라 아래 두 가지 인상이다.

1. **PC에서 "모바일 게임을 그대로 올린 것"으로 보인다.** 16:9 iframe의 약 30%만 게임이다.
2. **플레이의 깊이와 높이 체감이 얕다.** 매 낙하가 독립적인 성공/실패이고, 몇 개를 쌓아도 화면이 거의 같다.

둘 다 [결정]된 세로 구도·핵심 규칙과 관련되므로 사용자 결정이 필요하다.

## 개선 제안 (우선순위순)

### 1. PC 가로 화면 활용 — 가장 큰 인상 개선 [제안, 결정 필요]

- A. **옆 공간에 UI 배치**: 가로 창에서 COINS/BEST·콤보·일시정지·소리를 양옆 패널로 빼고 중앙 기둥은 동전과 탑만 남긴다. 세로 규칙·판정은 그대로다. 비용 중간.
- B. **가로 월드 확장**: 논리 화면은 유지하되 배경을 가로로 넓게 실제 렌더(흐림 없음)하고 탑을 중앙에 둔다. 가로 배경 아트 4장이 필요하다. 비용 큼.
- 권장: A부터. B는 아트 여유가 있을 때.

### 2. 높이 체감과 반복감 완화 [제안, 결정 필요]

- 배경을 적층 높이에 따라 아래로 천천히 흘려(패럴랙스) 실제로 올라간다는 느낌을 준다. 10개 단위 시간대 전환과 결합 가능.
- 이정표(10/25/50…) 통과 시 짧은 축하와 HUD 목표 표시(1차 검토 4번 제안과 동일).
- 핵심 규칙 변경 후보(가장 비용 큼): 치우친 착지의 누적으로 탑이 기울거나 흔들려 다음 판정에 영향을 주는 방식. 단순 성공/실패에 "이전 실수의 대가"를 더한다.

### 3. 플레이 중 화면 정리 [제안, 작은 범위]

- 안내 문구를 받침대 아트 위가 아닌 반투명 바탕 위나 하늘 영역에 둔다.
- 플레이 중에는 음소거/전체화면을 숨기거나 일시정지 메뉴로 옮긴다(1-A와 함께 처리 가능).

### 4. 메뉴·결과 명확성 [제안, 작은 범위]

- 메뉴 기록에 짧은 보이는 라벨(BEST / COMBO) 추가, 별조각 숫자 14px 이상.
- 결과에서 콤보가 0이면 콤보 줄을 숨긴다.

### 5. 작은 기술 마감 [제안, 작은 범위]

- 일시정지 키로 `P`를 추가하고 안내에 표시한다. Escape는 보조로 유지한다.
- SDK `loadingStart()`/`loadingStop()`을 필수 자산 로딩 구간에 보고한다(공통 서비스 계약 변경이므로 ARCHITECTURE 확인 후).

## 한계

- 실제 CrazyGames 호스트·실기기·사람의 재미 판단은 이번에도 확인하지 않았다. 리젝의 실제 원인을 확정할 수 없다.
- 40개 적층은 개발 훅으로 중앙을 기다려 낙하한 봇이며 사람의 난이도 근거가 아니다.
- 캡처는 세션 scratchpad에만 저장했고 저장소에 남기지 않았다.
