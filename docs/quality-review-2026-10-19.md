# Basic Launch 재신청 전 품질 검토

확인일: 2026-10-19. 실행물 기준: `2b0cc21`의 CrazyGames 배포본, 17,187,767 bytes / 40개 파일. 이번 작업은 검토이며 게임 코드·규칙·자산을 변경하지 않았다. 아래 개선안은 모두 [제안]이며 기존 확정 설계를 대체하지 않는다.

## 판단

후속 구현: 사용자가 요청한 1~3번(작은 화면·게임 오버 소리·로딩)을 적용했다. 이 문서의 수치는 검토 당시 기준으로 보존하며, 구현 후 결과와 남은 기기/사람 관측은 [최신 검증](VALIDATION.md)·[구현 계획](IMPLEMENTATION_PLAN.md)을 따른다.

이전보다 아트·조작 안내·성공/실패 표현·후반 난이도·수집 목표·음악의 연결이 정리됐다. 로컬에서 재현한 경로에 실행을 막는 오류는 없었다. 다만 **작은 PC 창의 정보 가독성·상점 복귀, 첫 진입 대기, 소리 마감**은 재신청 전에 보완할 가치가 있다. 첫 사용자에게 규칙이 쉽게 전달되고 다시 도전하고 싶은지는 아직 근거가 부족하다.

권장 순서는 작은 화면 정리와 소리 마감, 초기 로딩 개선, 신규 사용자 3판 관찰이다. 플레이 중 목표 표시를 작은 범위로 보강하는 것도 권장한다. 콘텐츠 확대는 그 관찰 결과를 보고 정한다. 검토로 CrazyGames의 승인 여부나 이전 리젝의 구체적 원인을 판정할 수는 없다. 당시 심사된 업로드의 정확한 빌드와 항목별 평가가 제공되지 않았다.

## 공식 기준의 적용 범위

[품질 가이드](https://docs.crazygames.com/requirements/quality/)는 실제 플레이 안의 안내, 명확한 목표, 반응·페이스·가독성, 적절한 소리와 일관된 미감을 권장한다. 항목별 합격 점수표는 아니다. [Gameplay 기준](https://docs.crazygames.com/requirements/gameplay/)에는 작은 DPR 1 프레임의 가독성과 입력·성능 등 제출 요건이 따로 있다.

이번 판단에 사용한 대응은 다음과 같다. 평가의 근거는 아래 실행 관측과 코드이며, 개선 우선순위는 이 프로젝트에 대한 해석이다.

| 관점               | 현재 상태                                                              | 남은 판단                                                |
| ------------------ | ---------------------------------------------------------------------- | -------------------------------------------------------- |
| 빠른 진입·안내     | 한 번의 시작 입력, 실제 플레이의 중심 눈금/제스처/SKIP, 안내 완료 저장 | 최초 두 번째 착지부터 규칙을 이해하는지 사람 관찰 필요   |
| 목표·페이스        | 결과의 다음 높이/스킨 목표, 10개 단위 배경, 계속 증가하는 속도         | 진행 중 목표 달성의 인지와 반복 플레이 동기는 미확인     |
| 기기별 가독성·조작 | 14px 이상 안내·44px 조작 영역, 9:16 FIT, 작은 프레임 대응              | 일부 보상 숫자와 상점 복귀는 개선 권장                   |
| 소리·화면의 일관성 | 네 스킨의 Perfect 색, 동일한 판타지 아트, 플레이 전용 BGM              | 임시 착지음의 적합성, 게임 오버 소리, 체감 음량 균형     |
| 식별성과 확장      | 스킨/배경/피드백 정의가 분리되고 커버가 게임의 소재와 일치             | 유사한 쌓기 게임 사이에서 기억에 남는지는 사람 평가 필요 |

[Basic Launch Guide](https://docs.crazygames.com/resources/basic-launch-metrics/)의 체류·재방문·전환 수치는 운영 테스트의 참고 지표다. 이 프로젝트에 고정 합격선이나 이번 재신청의 보장 조건으로 적용하지 않는다. [요구사항 소개](https://docs.crazygames.com/requirements/intro/)를 기준으로 현재 재신청은 Basic 단계이며, 기존 게스트 플레이와 비활성 광고 정책을 유지하는 범위다.

## 실제로 확인한 보완점

### 1. 작은 PC 창의 보상 숫자와 상점 복귀 — 우선 보완 권장

- [관측] 결과의 EARNED/TOTAL 숫자가 907×510에서 약 **13.34px**, 821×462에서 **12.04px**, 800×450에서 **11.72px**다. 주요 안내와 조작 버튼은 유지되지만, 이미 정한 가독성 목표에 맞춰 보상 숫자도 읽기 쉽게 만드는 편이 좋다. 여기서 14px는 프로젝트의 시작 기준이며 CrazyGames가 지정한 폰트 최소값은 아니다.
- [관측] 821×462의 상점에서는 아래 카드의 BUY 일부와 BACK이 접힌 영역 아래에 있다. 상점 내부 스크롤로 접근할 수 있으므로 탈출 불가 버그는 아니다. 하지만 첫 화면에 복귀 경로가 보이지 않고, 가격/부족분 문장이 여러 줄을 차지한다. 자동 브라우저의 버튼 클릭은 자동 스크롤을 하므로 이 불편을 가릴 수 있다.
- [제안] 보상 숫자에 최소 표시 크기를 적용하고, 작은 높이의 상점은 이미지/여백·가격 설명을 줄인다. 목록 스크롤과 별개로 BACK을 계속 보이게 하는 배치를 검토한다. 기존 세로 구도와 아이콘 방향은 유지할 수 있다.
- 완료 관측: DPR 1의 821×462·907×510·800×450에서 보상량을 읽고, 별도의 스크롤 탐색 없이 상점을 닫을 수 있다. 구매·장착·확인 버튼의 44px 조작 영역도 보존한다.
- 위치: `src/style.css`의 `.shard-reward strong`, `.skins-screen`, `.skin-card`, `.skin-state`, `.skins-back`; 상점 설명은 `src/ui/Shell.ts`.

### 2. 시작 전에 기다리는 자산 — 초기 이탈 관점의 보완 권장

- [관측] 캐시가 비어 있는 새 Chromium 세션에서 로컬 자산의 Resource Timing 전송 합은 PC/터치 모두 **16,137,183 bytes**다. CDP 합은 **16,135,763 bytes**로 계측 정의에 따른 차이가 있다. SDK는 페이지 시작 전에 주입한 통제 객체여서 이 수치에 포함되지 않는다. 실제 포털 Load 수치도 아니다.
- [관측] 같은 배포본의 로컬 10Mbps 다운로드·80ms latency 조건 한 번에서 시작 버튼 준비는 **14.05초**, 첫 Gameplay Start는 **14.53초**였다. 후자는 클릭 처리/대기까지 포함한다. 일반 로컬 조건에서는 준비가 약 1.10~1.27초였다. CPU 제한은 하지 않았다.
- [관측] 필수 로더가 네 배경·모든 스킨·119.573초 전체 음악을 읽고 나서 시작을 연다. 후반 배경 3장의 파일 합은 **3,900,258 bytes**, 추가 스킨은 **1,379,906 bytes**, 배경음은 **2,476,726 bytes**다.
- [해석] 현재 로컬 전송은 크기 측면에서 여유가 있지만, 중간 정도의 회선에서도 첫 플레이 대기가 길어질 수 있다. [기술 기준](https://docs.crazygames.com/requirements/technical/)의 초기 크기는 첫 Gameplay Start까지의 실제 다운로드로 보며, 파일 합과 동일시하지 않는다. 이번 10Mbps 조건은 내부 관측 조건이며 필수 심사 조건이 아니다.
- [제안] 첫 화면/기본 스킨/아침 배경의 필수 자산부터 시작하고, 후반 배경·미장착 스킨은 사용 전에 미리 불러오는 구조를 우선 검토한다. 숨김 상점의 HTML `<img src>`도 즉시 다운로드하므로 Phaser 로더와 HTML 양쪽을 함께 다뤄야 한다. 음악의 로딩 시점·해상도별 UI 이미지 최적화는 다음 조정 후보로 둔다.
- 완료 관측: 같은 조건의 새 세션에서 첫 플레이 진입을 다시 측정하고, 늦게 불러오는 스킨/배경의 첫 사용과 로딩 실패 경로를 확인한다. 10초 이내를 내부 개선 목표로 둘 수 있으나 확정 설계나 공식 합격선은 아니다.
- 위치: `src/game/assets.ts`, `src/scenes/PreloadScene.ts`, `src/ui/Shell.ts`, `src/game/art-manifest.json`.

### 3. 게임 오버와 착지 소리의 마감 — 재신청 전 권장

- [확인] 실패 순간 BGM을 끊는 동작은 구현됐지만 게임 오버 효과음은 아직 없다. 착지 소리는 템플릿의 0.18초 mono WAV 하나를 일반/Perfect의 rate·gain 차이로 재사용한다. 음악은 사용자 제공곡이다.
- [해석] 소리의 연결과 질감을 마지막으로 맞출 지점이다. 이번 검토에서 직접 청취한 것으로 판단하지 않으며, 임시 음원이라는 이유만으로 불합격이라고 보지는 않는다.
- [제안] 사용자가 예정한 짧은 게임 오버 효과음을 실패에 한 번 연결한다. 착지/Perfect도 실제 기기에서 음악과 함께 듣고 동전 소재에 어울리는지 판단한 뒤 필요한 파일만 교체한다.
- 완료 관측: 실패 한 번에 음악 종료와 효과음이 한 번 발생하고, 음소거·플랫폼 mute·중단/재개·재도전에서 이전 소리가 다시 울리지 않는다. NICE/Perfect를 음악 위에서 구분할 수 있으며 긴 플레이에서 피로하지 않은지는 사람이 듣는다.
- 위치: `src/game/controller.ts`, `src/game/feedback.ts`, `src/game/assets.ts`. 공통 오디오 수명은 `src/core/audio.ts`의 기존 계약을 따른다.

### 4. 플레이 중 다음 목표의 존재감 — 작게 보강 권장

- [확인] NEXT GOAL은 결과 화면에만 있다. 진행 중 HUD에는 COINS/BEST가 있고, 높이 목표를 통과했을 때 전용 달성 반응은 없다. Perfect는 기록용 칭찬이며 별조각 지급량은 성공 개수에 따른다.
- [가설] 처음에는 탭·쌓기·Perfect가 재미있더라도 몇 판 뒤에는 동일 행동과 속도 상승만 반복된다고 느낄 수 있다. 네 배경과 네 스킨은 외형 변화여서 이 가설을 단독으로 해소하지 않는다. 자동 고적층 성공은 사람의 재미나 재도전 의향을 입증하지 않는다.
- [제안] 기존의 다음 높이 목표를 플레이 중 작게 알려주고 5·10·20개 등 달성 순간에 짧은 축하를 주는 범위부터 검토한다. 이동 동전/목표를 가리지 않고 다음 낙하를 지연시키지 않으며 별도 보상을 약속하지 않는다. 확정된 집중형 HUD를 바꾸는 제안이므로 구현 전에 표현 범위를 정한다.
- 완료 관측: 사람이 진행 중 다음 목표를 말할 수 있고, 그 목표를 통과했다는 것을 알아본다. 숫자·연출을 더한 것이 다음 탭을 방해하지 않는지도 확인한다.
- 위치: `src/game/goals.ts`, `src/ui/Shell.ts`, `src/game/scenes.ts`; 기존 규칙은 `docs/design/records.md`와 `docs/design/feedback.md`.

### 5. 첫 두 번째 착지의 학습과 초반 난이도 — 먼저 사람 관찰

- [확인] 첫 동전은 어느 타이밍에도 받침대에 성공한다. 두 번째부터는 아래 동전 중심과의 차이로 판정한다. 안내는 현재 이동 중 제스처·중심 눈금·Align the coins 문구다. 실제 판정을 유지하며 실패도 가능하다.
- [가설] 첫 성공이 낙하 조작만 가르친 뒤, 두 번째부터 필요한 정렬 타이밍은 충분히 배우지 못할 수 있다. 그러나 현재 안내가 실패한다는 사람 관측도 없다.
- [제안] 처음 보는 사람에게 설명하지 않고 3판을 맡겨, 첫 실패 원인을 설명하는지와 다시 시도하는지 본다. 이해가 막히는 경우에만 첫 몇 번의 중심선/정렬 순간 신호를 보강한다. 속도·판정 폭·연습 전용 판정 변경은 별도 설계로 다룬다.
- 기록: 첫 자발적 낙하까지 걸린 시간, 3판의 실패 높이와 판 시간, 실패 이유 설명, 5개/첫 Perfect 도달, 재도전 의향. 실제 기기·빌드를 함께 적는다. 이 소규모 관찰을 전체 사용자 통계로 확대하지 않는다.

## 이미 나아졌거나 유지할 부분

- 기본 금화·네 스킨·배경·로고·실제 Perfect의 미감이 같은 밝은 판타지 방향을 유지한다. 검토한 커버도 동전 적층과 같은 소재를 표현한다. 새 아트를 일괄 교체할 근거는 이번 관측에서 찾지 못했다.
- 실제 입력, 안내 건너뛰기, NICE/Perfect 구분, 실패 동전의 방향, 결과의 다음 높이/스킨 목표가 이미 연결돼 있다. 구현된 항목을 다시 미구현 문제로 다루지 않는다.
- 후반 속도는 계속 증가하고 줌은 90%에서 멈춘다. 네 배경은 10개마다 바뀐다. 기능은 이전에 고적층/작은 화면에서 확인했으며, 이번에는 초반 신규 세션과 결과/상점을 집중 관측했다.
- 기본 마우스/키보드·터치, 사용자/플랫폼 음소거, 저장, 자체 전체화면 숨김·광고 비활성의 기존 검증은 [검증 기록](VALIDATION.md)을 따른다. 이번 캡처의 SDK 객체는 통제용이며 실제 CrazyGames 호스트 검증을 대신하지 않는다.
- 정확한 이름 검색에서 같은 CrazyGames 게임이 나오지 않았지만, 이것만으로 전체 유사성 검토가 완료된 것은 아니다. 이름 변경을 이번 재신청의 필수 작업으로 제안하지 않는다.

## 검토 방법과 한계

- 배포 코드 변경 없이 Chromium PC DPR 1·Pixel 7 터치 에뮬레이션 DPR 1의 새 브라우저 세션을 사용했다. 원래의 보유 스킨/점수/재화를 넣지 않고 기본 저장 상태에서 시작했다.
- 실제 버튼·마우스/터치를 사용해 첫 안내→두 번 성공→실패→결과→MENU→SHOP을 관측했다. 캡처 시점만 브라우저 시계로 제어했고 점수/동전 좌표를 덮어쓰거나 배포본에 게임 디버그 훅을 추가하지 않았다.
