# 기록과 리더보드

[게임 설계로 돌아가기](../GAME_DESIGN.md)

## 목적과 플레이 경험

[결정] 최고 적층 수와 Perfect 콤보 기록을 리더보드의 두 기록 항목으로 제공한다. 플레이어가 탑을 높이 쌓은 기록과 Perfect를 연속으로 성공한 기록을 각각 비교할 수 있게 한다.

## 기록의 정의

| 항목              | 한 판의 기록                                                             |
| ----------------- | ------------------------------------------------------------------------ |
| 최고기록          | 첫 실패까지 성공적으로 쌓은 동전 수. 실패한 동전은 제외한다.             |
| Perfect 콤보 기록 | 한 판에서 달성한 최장 연속 Perfect 횟수. 여러 연속 구간을 더하지 않는다. |

- [결정] 첫 동전은 Perfect 판정 대상이 아니므로 콤보 기록에 포함하지 않는다. Perfect가 없었던 판은 0, Perfect를 한 번만 성공한 판은 1이다.
- [결정] 현재 콤보와 그 판의 최장 콤보를 구분한다. NICE가 나오면 현재 콤보는 0이 되지만 그 판에서 달성한 최장 콤보는 유지한다. 실패로 현재 콤보가 초기화되어도 판의 최장 콤보로 기록을 확정한다.
- 판정·초기화·무제한 숫자 표시·연출 규칙은 [Perfect·콤보와 안내](../GAME_DESIGN.md#perfect콤보와-안내)를 따른다.

## 기록 확정과 보존

- [결정] 두 기록 모두 **첫 실패로 판이 끝날 때만** 확정한다. 플레이 도중의 개인 최고 경신은 아직 완료 기록으로 저장하거나 리더보드 기록으로 확정하지 않는다.
- [결정] 완료한 판의 각 기록을 해당 항목의 기존 개인 최고와 독립적으로 비교해 더 큰 값을 보존한다. 최고 적층 수와 최고 콤보는 서로 다른 판에서 나온 값이어도 된다.
- [결정] 일시정지·탭 전환·재개 카운트다운은 현재 콤보와 판의 최장 콤보를 보존한다. 기존 중단·재개 규칙을 따른다.
- [결정] 실패 전에 RESTART·MENU로 판을 중단하거나 새로고침·페이지 종료를 하면, 그 판의 적층 수와 최장 콤보는 모두 기록에서 제외한다. 이미 저장된 개인 최고는 유지한다. 새 판의 현재 콤보와 판의 최장 콤보는 0에서 시작한다.
- [결정] 완료 결과는 한 번만 확정한다. 완료 후 TRY AGAIN·MENU로 이동해도 다시 기록하거나 기존 개인 최고를 지우지 않는다.
- [결정] 정상 저장된 브라우저 기록은 같은 브라우저·같은 사이트에서 새로고침 후에도 유지한다. 저장할 수 없을 때도 플레이를 허용하고 저장 실패를 알리며 저장되었다고 표시하지 않는다.
- [결정] 템플릿 데모 기록과 모바일 원본 기록은 새 웹 기록에 합치지 않는다.

## 전역 리더보드 규칙

### 집계 기간과 개인 기록

- [결정] 최고 적층 수와 최장 Perfect 콤보의 **두 순위표를 독립적으로** 제공한다. 각 순위표는 전체 기간의 개인 최고를 비교하며 정기 초기화하지 않는다. 주간·시즌 순위는 이번 범위에 포함하지 않는다.
- [결정] 계정마다 각 순위표에 개인 최고 하나씩 등록한다. 점수를 누적하거나 여러 판의 콤보를 합산하지 않는다. 두 항목의 최고가 서로 다른 완료 판에서 나와도 된다.
- [결정] 각 항목은 큰 값이 높은 순위다. 기존 값보다 낮거나 같은 기록은 개인 최고를 바꾸지 않으며, 동점 기록을 다시 제출해 최초 달성 순서를 바꾸지 않는다.

### 동점 처리

- [결정] 같은 기록은 공동 순위로 표시한다. 공동 순위 다음에는 그 인원만큼 순위를 건너뛴다. 예: 기록이 50·50·40이면 **1위·1위·3위**다.
- [결정] 동점자 사이의 표시 순서만 해당 기록을 먼저 달성한 순으로 정한다. 표시 순서로 공동 순위를 나누거나 다른 기록 항목을 보조 점수로 사용하지 않는다.
- 달성 순서의 신뢰 가능한 판정 기준과 지연 전송 처리는 아래 서비스 결정에서 확정한다.

### 참가 조건

- [결정] 게임 플레이와 순위 열람은 로그인 없이 허용한다. 순위 등록을 위해 플레이 시작을 로그인 화면으로 막지 않는다.
- [결정] 전역 순위 등록은 **CrazyGames 로그인 사용자**의 완료 판을 대상으로 한다. 게스트도 기존 브라우저 개인 최고 저장·결과 표시를 이용할 수 있다.
- [결정] 완료 판의 인정·중단 제외 기준은 [기록 확정과 보존](#기록-확정과-보존)을 따른다. 진행 중인 판의 경신을 전역 순위 기록으로 확정하지 않는다.
- [결정] 콤보 순위는 **1 이상부터** 등록한다. 콤보 0은 브라우저 개인 기록과 결과 화면에 계속 표시하며 콤보 순위에는 등록하지 않는다. 같은 완료 판의 적층 기록은 별도로 등록 대상이 된다.
- 이 참가 조건은 전역 순위의 계정 식별 범위다. 기존 브라우저 개인 기록을 계정 기록으로 이전하거나 기기 간 동기화하는 동작은 별도 결정이 필요하다.

## 결과·메뉴의 기록 표시

### 결과 화면

- [결정] `GAME OVER` 아래의 비교 패널에 두 기록을 같은 비중의 두 행으로 표시한다. 위 행은 `COINS`, 아래 행은 `PERFECT COMBO`다. 열 제목은 `THIS RUN`과 `BEST`다.
- [결정] `THIS RUN`은 이번 완료 판의 적층 수와 최장 연속 Perfect 횟수다. `BEST`는 이번 판을 반영한 각 항목의 개인 최고다. 실패로 초기화된 현재 콤보를 결과로 표시하지 않는다.
- [결정] 적층 수는 숫자, 콤보는 `x`를 붙인 숫자로 표시한다. Perfect가 없으면 `x0`, 한 번이면 `x1`도 숨기지 않는다.
- [결정] 이번 판의 값이 판 종료 직전 개인 최고를 **초과한 항목에만** 결과 화면에 `NEW BEST`를 붙인다. 동점은 경신이 아니다. 두 항목을 모두 경신하면 각 행에 표시한다.
- [결정] 기록 패널 아래에는 기존 `TRY AGAIN`·`MENU` 버튼을 유지한다. 두 기록은 기존 파란 패널과 금색 숫자를 사용한다.

예시: 이전 개인 최고가 적층 수 30·콤보 8이고 이번 판이 적층 수 20·최장 콤보 12로 끝났을 때다.

| 항목          | THIS RUN | BEST |
| ------------- | -------- | ---- |
| COINS         | 20       | 30   |
| PERFECT COMBO | x12      | x12  |

이 결과에서는 `PERFECT COMBO` 행에만 `NEW BEST`가 표시된다. 저장 실패 안내와 보존은 [기록 확정과 보존](#기록-확정과-보존)을 따른다.

### 메뉴 화면

- [결정] 로고 아래 기존 기록 영역을 좌우 두 칸으로 구성하고 두 개인 최고를 같은 크기로 표시한다. 공통 제목은 `BEST ON THIS BROWSER`, 왼쪽은 `BEST COINS`, 오른쪽은 `BEST COMBO`다.
- [결정] 메뉴에는 개인 최고만 표시한다. 이번 판의 결과 비교와 `NEW BEST` 표시는 결과 화면에서 제공한다.
- [결정] 위 결과 예시 이후 메뉴에는 `BEST COINS` 30, `BEST COMBO` x12가 표시된다. 정상 저장 후 새로고침해도 같은 값을 표시한다.

### 화면에서 확인할 조건

- 두 기록의 항목 이름·이번 판·개인 최고 관계가 분명하며, 버튼이나 숫자가 서로 겹치지 않는다. 기존 로고·동전·받침대와 시작·재시도 조작 영역을 유지한다.
- x0·x1·x10·x100을 PC·모바일 세로 화면과 작은 가로 포털 화면에서도 읽을 수 있어야 한다. 실제 가독성과 영역 비가림은 구현 후 화면 관측으로 확인한다.
- 중단한 판은 메뉴의 두 개인 최고를 바꾸지 않는다. 결과 화면에서 첫 실패 뒤 콤보가 0으로 초기화되더라도 이번 판 최장 콤보는 표시된다.

## 관찰 가능한 결과

1. `Perfect 8회 → NICE → Perfect 5회 → 실패`인 판의 콤보 기록은 **8**이다. 마지막 콤보 5나 누적 Perfect 13을 기록하지 않는다.
2. `Perfect 8회 → NICE → RESTART`인 판은 두 기록 모두 갱신하지 않는다. 이전에 완료해 저장한 개인 최고는 남는다.
3. `Perfect 5회 → 일시정지 → 재개 → Perfect 1회`이면 현재 콤보와 판의 최장 콤보는 6이다. 실패하면 6을 완료 기록으로 비교한다.
4. 기존 최고 적층 수가 30, 최고 콤보가 8이고 새 판이 적층 수 20·최장 콤보 12로 끝나면, 개인 최고는 적층 수 **30**·콤보 **12**가 된다.
5. 위 판의 결과 화면에는 `COINS` 20/30, `PERFECT COMBO` x12/x12가 보이며 콤보 행만 `NEW BEST`다. 메뉴에는 30·x12가 보인다.
6. 이전 개인 최고가 적층 수 30·콤보 12이고 이번 판도 같은 값이면 두 행 모두 `NEW BEST`를 표시하지 않는다. 두 최고를 모두 초과한 판은 두 행 모두 표시한다.
7. 전역 적층 기록이 50·50·40인 세 계정의 순위는 1·1·3이다. 동점자는 먼저 50을 달성한 계정을 위에 표시하지만 둘 다 1위다. 같은 50을 다시 제출해도 달성 순서는 바뀌지 않는다.
8. 주가 바뀌어도 두 전역 순위표의 기록은 초기화되지 않는다. 새로운 완료 판에서 콤보만 경신하면 콤보 순위만 갱신하며 적층 개인 최고는 유지한다.
9. 게스트는 플레이와 순위 열람이 가능하며 완료 판의 브라우저 개인 최고를 저장한다. 전역 순위에는 등록하지 않는다. 로그인 사용자도 실패 전 중단한 판은 등록하지 않는다.
10. 로그인 사용자가 Perfect 없이 판을 완료하면 적층 기록은 등록 대상이고 콤보 순위에는 새 항목을 만들지 않는다. 결과 화면의 이번 판 콤보는 `x0`이다. 이후 완료 판에서 Perfect 1회를 달성하면 콤보 기록 1을 등록할 수 있다.

## 영향을 받는 시스템

- [Perfect·콤보](../GAME_DESIGN.md#perfect콤보와-안내): 현재 연속 횟수와 판의 최장 횟수를 구분하고 5회 이상도 실제 숫자를 표시한다.
- [일시정지·재개·중단](../GAME_DESIGN.md#일시정지재개중단): 중단과 완료를 구분하는 기준이며 재개 중에는 판의 기록을 보존한다.
- [재시작·결과](../GAME_DESIGN.md#재시작결과최고-기록): 새 판의 임시 상태 초기화와 완료 결과 보존에 영향을 준다.
- 저장·리더보드 화면: 두 항목의 개인 최고 보존, 완료 결과 전달, 저장 실패 안내에 영향을 준다. 서비스와 화면의 세부 결정은 아래 미결 항목을 따른다.
- 계정·전역 순위: CrazyGames 로그인 사용자 식별, 로그인 없는 순위 열람, 두 항목의 독립 갱신과 공동 순위 표시가 필요하다. 브라우저 개인 기록과 전역 등록 기록의 적용 범위를 구분한다.

## 남은 결정과 구현 상태

### 플랫폼 제약과 미결 항목

- 확인 근거(2026-10-08): [CrazyGames 공식 리더보드 문서](https://docs.crazygames.com/sdk/leaderboards/)는 초대된 게임만 사용 가능, 게임당 순위표 하나, 매주 월요일 09:00 UTC 초기화를 명시한다. [User 문서](https://docs.crazygames.com/sdk/user/)는 계정 기능의 사용 가능 여부를 확인하도록 안내한다. 실제 프로젝트의 초대 여부는 확인하지 않았다.
- 이 제약을 기준으로 보면 합의한 두 전체 기간 순위표를 공식 리더보드 기능만으로 충족할 수 없다. 별도 순위 서비스 또는 자체 서비스의 선택이 필요하다. 공급자는 아직 선택하지 않았다.
- 서비스 조사를 완료했다. [후보 비교와 권장안](../research/leaderboard-services.md)은 **[제안] Supabase Postgres + Edge Functions**를 권장하며 Cloudflare Workers+D1·Firebase를 비교한다. 인증 경계·비용·검증 한계와 공식 출처를 포함한다. 공급자·운영 정책은 미확정이며 실제 계정 연결·배포는 수행하지 않았다.
- [미결] 순위 화면 구성, 순위 서비스·계정 인증 연결·기록 검증 수준, 최초 달성 순서의 판정 기준, 조회·전송 실패 안내와 재시도 정책.
- [미결] 로그인 전 브라우저 기록의 이전 여부, 판 도중 로그인·계정 변경 처리, 계정 기능이 없는 배포 환경의 순위 등록 범위. 게스트 플레이·열람 허용과 로그인 사용자만 등록한다는 원칙은 유지한다.
- 위 미결 항목의 첫 구현 제안과 단계별 확인 조건은 [구현 계획](../IMPLEMENTATION_PLAN.md)에 있다. 제안은 사용자 확인 후 이 문서의 해당 규칙으로 확정한다.

### 구현 상태

- 결과·메뉴의 두 기록 표시와 항목별 `NEW BEST`를 구현했다. 결과에는 완료한 판의 두 값과 갱신된 개인 최고, 메뉴에는 두 개인 최고를 표시한다. 실제 확인 환경과 제한은 [검증 기록](../VALIDATION.md)을 따른다.
- 현재 실행물은 무제한 콤보 표시와 완료 시 브라우저 개인 최고 적층 수·최장 콤보의 독립 저장을 구현했다. 저장 형식 v2는 기존 v1의 최고 적층 수·완료 판 수를 보존하고, 이전에 기록하지 않았던 최고 콤보는 0으로 시작한다. 로컬 저장을 전역 리더보드 구현으로 간주하지 않는다.
- 현재 브라우저 기록은 다른 브라우저·기기와 공유하지 않는다. 전역 순위와 기기 간 저장 공유의 범위는 서비스 결정에서 구분한다.
- 전역 리더보드의 집계 기간·동점·참가 조건은 확정했다. 실제 연결은 미결 서비스 정책을 정한 뒤 별도로 진행하며, 로그인·전역 조회·등록은 아직 구현하지 않았다.
